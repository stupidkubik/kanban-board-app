## Known dependency risk

`npm audit --omit=dev` reports 11 production-tree entries:

- Next.js transitively includes vulnerable PostCSS and Sharp ranges;
- Firebase Admin 13.x transitively includes Google Cloud and UUID advisories.

There is no compatible automated fix. `firebase-admin` 14.x remains blocked by
the confirmed Vercel `ERR_REQUIRE_ESM` runtime failure through
`jwks-rsa@4 -> jose@6`. Do not run `npm audit fix --force`; follow
`docs/DEPENDENCY_POLICY.md` and repeat a preview migration when compatible
upstream releases exist.

## Migration repair and rollback

Both release dry-runs are clean, so no migration rollback is required.

Before any future card-label apply:

1. run the dry-run and retain its per-board output;
2. export affected boards, cards, and label subcollections;
3. apply only after the export is verified;
4. re-run the dry-run and expect zero pending changes.

If repair is required, reconstruct each legacy `labels` array from the referenced
catalog document names, restore the controlled export, and only then remove
generated `labelIds`/catalog entries. The migration has no automatic destructive
rollback. Stale-profile deletion is likewise restored only from a controlled
backup, as documented in `docs/MIGRATION_STALE_MEMBER_PROFILES_2026-07-27.md`.

For application rollback, reassign the production alias to the previous known
good deployment `dpl_GZB8xV5bwcBKrKonmPmuGFJufDcm`. The phase 8 schema is
backward-readable during rollback: cards retain compatibility reads for legacy
label strings, and the new optional catalog fields do not invalidate older
documents.
